# Goal

Allow bounded `discovered`, `normalized` and `review-needed` evidence packages to pass full source-contract validation without publishing them into deterministic module/global factual indexes or treating their observation date as part of the currently published `as_of` boundary.

# Proven failure

- The evidence CLI currently validates every record against the workflow `as_of` date and generates indexes from every record regardless of `record_status`.
- RTEC-005 workers are contractually forbidden from editing the coordinator-owned shared generated index.
- Honest worker evidence observed on 2026-07-26 therefore fails the workflow fixed at `--as-of 2026-07-25` and also causes deterministic global-index drift before coordinator review.
- The source library exposes enough immutable corpus documents to build a filtered publication view without weakening source-contract validation.

# Intended behavior

- Validate every record, source, reference, history and dossier contract, including prepublication records.
- Exclude only `discovered`, `normalized` and `review-needed` records from the publication view used for freshness and generated-index checks.
- Exclude requests and version-history entries whose claim references are not wholly published.
- Keep accepted, conflicting, blocked, rejected, stale and superseded adjudicated records in published indexes.
- Do not alter schemas, record formats, owner-request states or existing generated bytes on current `main`.
- Require coordinator acceptance before candidate evidence changes published module/global indexes.

# Acceptance criteria

- [ ] Add one deterministic publication-view helper in the existing CLI.
- [ ] Preserve full fail-closed validation for all non-index source-contract diagnostics.
- [ ] Make `validate`, `generate --check` and `show-index` use the publication view for freshness/index operations.
- [ ] Add focused tests proving a future-dated `review-needed` record validates but remains absent from generated indexes.
- [ ] Add focused tests proving an accepted future-dated record still fails the publication `as_of` gate.
- [ ] Document the review-to-publication boundary and coordinator responsibility.
- [ ] Update the module catalogue reuse contract.
- [ ] Confirm the PR changes no generated evidence index, workflow, schema, runtime, data, client, map or E2E path.
- [ ] Pass focused tests, Evidence Contracts, Agent Task Ownership and ordinary CI on the exact head.
- [ ] Apply the final-head gate, mark Ready and squash-merge before refreshing RTEC-005 workers.
