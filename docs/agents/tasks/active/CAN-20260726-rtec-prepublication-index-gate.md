# Goal

Allow bounded `discovered`, `normalized` and `review-needed` evidence packages to pass full source-contract validation without publishing them into deterministic module/global factual indexes or treating their observation date as part of the currently published `as_of` boundary.

# Proven failure

- The evidence CLI validated every record against the workflow `as_of` date and generated indexes from every record regardless of `record_status`.
- RTEC-005 workers are contractually forbidden from editing the coordinator-owned shared generated index.
- Honest worker evidence observed on 2026-07-26 therefore failed the workflow fixed at `--as-of 2026-07-25` and also caused deterministic global-index drift before coordinator review.
- The source library exposes immutable corpus documents that support a filtered publication view without weakening source-contract validation.

# Implemented behavior

- Every candidate record, source, reference, history and dossier contract remains validated.
- Only `discovered`, `normalized` and `review-needed` records are excluded from the publication view used for freshness and generated-index checks.
- Requests and version-history entries are published only when all claim references are already published.
- Accepted, conflicting, blocked, rejected, stale and superseded adjudicated records remain published.
- `validate`, `generate --check` and `show-index` now use the same deterministic publication view.
- Existing schemas, record formats, owner-request states, workflow and generated bytes remain unchanged.
- Coordinator acceptance remains the boundary that advances candidate evidence into module/global indexes.
