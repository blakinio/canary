# Tibia content reference correlation

TCR-006 adds deterministic, read-only correlation between the stable manifest-bound StaticData index and evidence already owned by Canary's Achievement, Cyclopedia, Spawn/Boss/NPC and Quest validation modules.

Stable public formats:

```text
canary-tibia-content-reference-resolver-v1
canary-tibia-content-reference-correlation-v1
```

The compact `canary-tcr006-owner-inventory-v1` document is an intermediate exact-input artifact. It is generated by calling existing subsystem-owner functions; it is not a replacement scanner and is not a gameplay authority.

## Evidence model

Source vocabulary is preserved exactly:

- legacy `creatures` remain creatures;
- newer `monsters` remain monsters;
- legacy `titles` remain titles and are not silently renamed achievements;
- newer `achievements` remain achievements;
- `bosses`, `monsterClasses` and `quests` remain separate dimensions;
- houses are excluded because TCR-005 owns house correlation.

Target evidence is routed to existing owners:

| Source dimension | Existing target owner | Target namespace |
|---|---|---|
| `creatures` / `monsters` identity | Cyclopedia Bestiary inventory | `canary-bestiary-race-id` |
| `creatures` / `monsters` definition presence | Spawn/Boss/NPC definition inventory | `canary-monster-definition-path` |
| `bosses` identity | Cyclopedia Bosstiary inventory | `canary-bosstiary-boss-race-id` |
| `bosses` definition presence | Spawn/Boss/NPC definition inventory | `canary-monster-definition-path` |
| `titles` / `achievements` | Achievement Validation registry | `canary-achievement-id` |
| `quests` | Quest Map Validator plus Storage/Quest State owners | no automatic shared ID namespace |

## Resolver policy

A mapping is emitted only under one reviewed method:

- `reviewed-unique-id-name`: one target row owns the numeric ID and its normalized name matches exactly;
- `reviewed-unique-id-name-grade`: the ID and normalized name match uniquely and the title/achievement grade also matches;
- `reviewed-unique-normalized-name`: one active monster definition has the exact normalized source name; this proves definition presence only and never proves technical ID equivalence.

Shared target IDs, missing target IDs, mismatched names/grades, duplicate source IDs, stale hashes and invalid target ordinals fail closed. Numeric equality by itself is never accepted. Quest names never select source globs, AID/UID values, storage paths or map evidence.

## Intermediate owner inventory

```bash
PYTHONPATH=tools/ai-agent \
python tools/ai-agent/tibia_content_reference_correlation_tool.py inventory \
  --repository-root . \
  --output /tmp/TCR006_OWNER_INVENTORY.json
```

The command reuses:

- `achievement_validation.parse_registry_text`;
- `cyclopedia_validation.collect_monsters`;
- `otbm_spawn_npc.scan_active_datapack`.

It retains only compact factual ID/name/path metadata, repository head, owner summary and source hash evidence. It does not include client files, full owner reports or runtime conclusions.

## Derive reviewed resolver

```bash
python tools/ai-agent/tibia_content_reference_correlation_tool.py derive-resolver \
  --staticdata-index /outside-git/TIBIA_STATICDATA_REFERENCE_INDEX.json \
  --owner-inventory /tmp/TCR006_OWNER_INVENTORY.json \
  --review-id tcr006-reviewed-owner-join-20260724 \
  --review-statement "Exact reviewed unique mappings only." \
  --output /tmp/TCR006_CONTENT_RESOLVER.json
```

The resolver pins the exact StaticData index SHA-256, its manifest/source provenance, the exact owner inventory SHA-256 and target repository head.

## Build correlation

```bash
python tools/ai-agent/tibia_content_reference_correlation_tool.py correlate \
  --staticdata-index /outside-git/TIBIA_STATICDATA_REFERENCE_INDEX.json \
  --owner-inventory /tmp/TCR006_OWNER_INVENTORY.json \
  --resolver /tmp/TCR006_CONTENT_RESOLVER.json \
  --output /tmp/TCR006_CONTENT_CORRELATION.json
```

Per-source states are:

- `confirmed-reference`: the reviewed identity mapping is present and, for creatures/bosses, active definition presence is also confirmed;
- `partial`: only one of identity or definition presence is confirmed;
- `reference-only`: no target candidate was found;
- `unresolved-id-space`: target evidence exists but the cross-namespace join is unsupported, shared or mismatched;
- `conflicting` / `stale-evidence`: reserved fail-closed states for reviewed conflict and provenance failure;
- `target-only`: target-owner evidence was not consumed by an identity mapping.

## Exact reviewed result for the supplied legacy StaticData snapshot

The exact outside-Git evidence used during TCR-006 development contains 812 creatures, 356 titles, 438 bosses and 99 quests. The reviewed unique rules produce:

- 739 creature-to-Bestiary identity mappings;
- 236 boss-to-Bosstiary identity mappings;
- 349 title-to-achievement identity mappings;
- 748 creature and 346 boss active-definition presence mappings;
- 1324 `confirmed-reference`, 119 `partial`, 160 `reference-only` and 102 `unresolved-id-space` source rows;
- all 99 quest rows remain `unresolved-id-space` until explicit reviewed quest-source selections exist;
- zero conflicts.

These counts are evidence for this exact StaticData/owner snapshot only. They are not universal Tibia or Canary parity claims.

## Boundaries

- no StaticData reparsing;
- no second Achievement, Cyclopedia, Spawn/Boss/NPC or Quest validator;
- no fuzzy-name matching;
- no automatic quest source selection;
- no map, source, datapack, protocol, database or client mutation;
- no runtime, persistence, reachability or gameplay conclusion;
- no TCR-007 proficiency work.

Outputs are deterministic UTF-8 JSON written atomically. Existing outputs require `--overwrite`; symlink outputs and input/output aliases are rejected. Exact generated inventories, resolvers and reports stay outside Git.
